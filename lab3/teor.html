Java ООП: Полный экзаменационный конспект

Слайды 15–40. Дословные формулировки из презентации + каверзные вопросы в текстовом виде (что выведет / что сломается).

1. Инкапсуляция, Модификаторы доступа и Пакеты (Слайды 15–17)

Определение из лекции: Инкапсуляция
  1. Данные и поведение объединяются в одном объекте (классе).
  2. Внутренняя реализация скрывается.
  3. Взаимодействие с полями только через доступные методы.
Определение из лекции: java.package

Пакет (package) — это группа классов, объединенных по функциональности.

  • Объявляется в начале файла: package com.example.myapp; — всегда первая строка файла!
  • Логическая группировка (как папки на диске).
  • Избегание конфликтов имен.
  • Контроль доступа (package-private виден только в пакете).
Модификатор Класс Пакет Наследник (другой пакет) Весь код
public ✓ ✓ ✓ ✓
protected ✓ ✓ ✓ ✗
(default) package-private ✓ ✓ ✗ ✗
private ✓ ✗ ✗ ✗
❓ Препод в .txt: «Что будет при попытке скомпилировать класс B?» 
// Файл: p1/A.java
package p1;
public class A {
    protected int x = 10;
    int y = 20; // package-private
}

// Файл: p2/B.java
package p2;
import p1.A;

public class B extends A {
    public void print() {
        System.out.println(this.x); // (1)
        A other = new A();
        System.out.println(other.x); // (2)
        System.out.println(this.y);  // (3)
    }
}
Ошибка компиляции на строках (2) и (3)

Почему:

  • (1) this.x компилируется: класс B является наследником A и видит унаследованное поле protected.
  • (2) other.x — ОШИБКА: доступ к protected полю объекта другого класса через прямую ссылку разрешен только внутри пакета p1. Потомок в другом пакете имеет доступ к нему только через механизм наследования (в себе), а не на произвольном экземпляре new A().
  • (3) this.y — ОШИБКА: поле default (package-private) вообще не наследуется и не видно за пределами пакета p1.

2. Неизменяемые классы (Immutable) и Record (Слайды 18–20)

Определение из лекции: Immutable класс

Immutable класс — объект нельзя изменить после создания.

Правила создания:

  • Все поля private final.
  • Нет сеттеров.
  • Класс объявлен как final (чтобы нельзя было отнаследовать и сломать).
  • Если поле — изменяемый объект (например, Date или массив), возвращаем/принимаем его копию.

Примеры встроенных неизменяемых классов: String, Integer, Double, LocalDate, BigDecimal.

Определение из лекции: Record (с Java 14+)

Компактная запись неизменяемого класса с данными в одну строку: public record PointRecord(int x, int y) {}

Автоматически генерирует: конструктор, поля private final, equals(), hashCode(), toString() и методы доступа вида p.x() и p.y() (без префикса get!).

❓ Препод в .txt: «Является ли данный класс неизменяемым? Что выведет main?» 
public final class Team {
    private final List<String> members;

    public Team(List<String> members) {
        this.members = members;
    }
    public List<String> getMembers() {
        return members;
    }
}

// В main:
List<String> list = new ArrayList<>();
list.add("Иван");
Team t = new Team(list);
t.getMembers().add("Петр");
System.out.println(t.getMembers().size());
Выведет: 2 (Класс НЕ является неизменяемым!)

Почему: Нарушено 4-е правило: «Если поле изменяемый объект, возвращаем/принимаем его копию». Передана прямая ссылка на изменяемый ArrayList. Модификатор final защищает лишь саму ссылку от перезаписи, но не запрещает менять состав коллекции.

Как исправить:

public Team(List<String> members) {
    this.members = List.copyOf(members); // Защитная копия при приеме
}
public List<String> getMembers() {
    return members; // List.copyOf уже неизменяемый, либо List.copyOf(members)
}

3. Наследование, super и Порядок инициализации (Слайды 21–25)

Определение из лекции: Наследование

Наследование — механизм ООП, позволяющий одному классу (наследнику) получать свойства и методы другого класса (родителя).

Отношение "is-a" (является): Наследник является разновидностью родителя.

  • Собака является Животным.
  • Студент является Человеком.
  • ArrayList является List.
  • Ключевое слово extends используется для наследования.
  • В Java класс может наследоваться только от одного родителя (единичное наследование).
  • Наследник получает все public и protected (package-private если в одном пакете) поля и методы родителя.
Определение из лекции: super

super — ссылка на родительский класс (аналог this для родителя). Используется в трех случаях:

  1. Вызов конструктора родителя: super(параметры) — должен быть первой строкой!
  2. Доступ к полю родителя (если оно перекрыто): super.field.
  3. Вызов метода родителя (если он переопределен): super.method().

Правило конструктора: Если в родительском классе нет конструктора по умолчанию — необходимо вызвать конструктор с параметрами родительского класса вручную через super(...).

Порядок инициализации при создании объекта-наследника
  1. Статические поля и статические блоки родителя
  2. Статические поля и статические блоки потомка
  3. Нестатические поля и блоки инициализации родителя
  4. Конструктор родителя
  5. Нестатические поля и блоки инициализации потомка
  6. Конструктор потомка
❓ Препод в .txt: «Что напечатает код? (Ловушка на порядок и сокрытие полей)» 
class Parent {
    int a = 10;
    Parent() {
        System.out.println("Parent constr, a = " + a);
    }
}

class Child extends Parent {
    int a = 20;
    Child() {
        System.out.println("Child constr, a = " + a);
    }
}

public class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        System.out.println("Field: " + p.a);
    }
}
Вывод в консоль: 
Parent constr, a = 10
Child constr, a = 20
Field: 10

Почему Field: 10, а не 20? Поля в Java не полиморфны! Поле a в Child перекрыло (shadowed/hidden), а не переопределило поле родителя. При обращении к полю через переменную типа Parent (ссылка p), компилятор берет поле родителя. Полиморфизм работает ТОЛЬКО для методов!

4. Переопределение (@Override) и модификатор final (Слайды 26–28)

Определение из лекции: Переопределение методов (Override)

Переопределение (Override) — изменение реализации метода наследника, который уже есть у родителя.

Правила переопределения:

  • Имя и сигнатура (параметры) должны совпадать.
  • Возвращаемый тип должен быть совпадающим или ковариантным (подтипом).
  • Модификатор доступа нельзя сужать (можно расширять): protected → public (можно), public → protected (нельзя).
  • Нельзя переопределить final или static методы.
  • Нельзя переопределить private методы (они не наследуются).
Определение из лекции: Модификатор final (запрет наследования)
  • final класс — от него нельзя наследоваться.
  • final метод — его нельзя переопределить в наследнике.
  • final поле — его нельзя изменить после инициализации (константа).
❓ Препод в .txt: «Где здесь ошибки компиляции?» 
class SuperClass {
    Number getNum() { return 1; }
    public void action() {}
    static void test() {}
}

class SubClass extends SuperClass {
    // Метод 1
    @Override
    Integer getNum() { return 2; }

    // Метод 2
    @Override
    protected void action() {}

    // Метод 3
    @Override
    static void test() {}
}
Ошибки в Метод 2 и Метод 3
  • Метод 1 — скомпилируется: Возвращаемый тип Integer является подтипом Number (ковариантный тип возврата разрешен).
  • Метод 2 — ОШИБКА: Сужение модификатора доступа с public до protected строго запрещено.
  • Метод 3 — ОШИБКА: Статические методы принадлежат классу, а не экземпляру, их нельзя пометить @Override. В потомке статический метод с такой же сигнатурой лишь скроет метод родителя (method hiding).

5. Приведение типов, instanceof и Полиморфизм (Слайды 29–33)

Определения из лекции: Upcasting и Downcasting
  • Upcasting (восходящее приведение) — приведение от наследника к родителю. Происходит автоматически.
  • Downcasting (нисходящее приведение) — приведение от родителя к наследнику. Требует явного кастинга и проверки. Ошибка при некорректном downcasting приводит к ClassCastException в runtime.
Определение из лекции: instanceof

instanceof — проверяет, является ли объект экземпляром определенного класса (или его наследника). Возвращает boolean.

Начиная с Java 14, поддерживает pattern matching (связывание переменной): if (animal instanceof Dog dog) { dog.bark(); }

Определение из лекции: Полиморфизм

Полиморфизм (от греч. «много форм») — способность объектов с одинаковым интерфейсом иметь разную реализацию. Один и тот же метод ведет себя по-разному для разных объектов.

  • Статический полиморфизм (Compile-time / Early binding): Перегрузка методов (Overloading) — методы с одинаковым именем, но разными параметрами. Компилятор определяет метод на этапе компиляции.
  • Динамический полиморфизм (Runtime / Late binding): Переопределение методов (Overriding) — наследник изменяет реализацию метода родителя. JVM определяет, какой метод вызвать, во время выполнения программы (на основе реального типа объекта). JVM использует dynamic binding — ищет метод в реальном типе объекта, а не в типе ссылки.
❓ Препод в .txt: «Что произойдет при выполнении этого блока кода?» 
class Bird {
    void fly() { System.out.println("Птица летит"); }
}
class Penguin extends Bird {
    @Override
    void fly() { System.out.println("Пингвины не летают!"); }
}

public class Main {
    public static void main(String[] args) {
        Bird b = new Penguin(); // Upcasting
        b.fly();                // (1)
        
        Bird realBird = new Bird();
        Penguin p = (Penguin) realBird; // (2) Downcasting
        p.fly();
    }
}
Вывод: "Пингвины не летают!", а затем ClassCastException

Разбор:

  • (1) Сработает динамический полиморфизм: ссылка типа Bird указывает на реальный объект в памяти Penguin. Вызовется переопределенный метод пингвина.
  • (2) Код скомпилируется, но упадет в runtime на строке каста: объект в памяти действительно создан как new Bird(), JVM не может привести его к типу Penguin. Чтобы избежать ошибки, обязательна проверка через if (realBird instanceof Penguin p).

6. Абстракция, Абстрактные классы и Интерфейсы (Слайды 34–39)

Определение из лекции: Абстракция

Абстракция — выделение существенных характеристик объекта и отвлечение от несущественных. Позволяет создавать «шаблоны» для будущих классов.

Определение из лекции: Абстрактный класс и Абстрактный метод

Абстрактный класс — класс, который:

  • Объявлен с ключевым словом abstract.
  • Не может быть инициализирован (нельзя сделать new AbstractClass()).
  • Может содержать абстрактные методы (без реализации) и обычные методы (с реализацией).
  • Может иметь поля, конструкторы, статические методы.

Абстрактный метод — метод без тела (реализации). Объявляется с ключевым словом abstract.

  • Может быть только в абстрактном классе или интерфейсе.
  • Наследник обязан реализовать все абстрактные методы родителя (или стать абстрактным сам).
  • Не может быть private (иначе наследник не сможет его реализовать).
  • Не может быть static (статические методы не переопределяются).
  • Не может быть final (final методы нельзя переопределять).
Определение из лекции: Интерфейсы (interface)

Интерфейс — это контракт, описывающий что должен уметь делать класс, но не как.

  • Объявляется ключевым словом interface. Класс реализует его через implements.
  • Класс может реализовывать несколько интерфейсов (в отличие от наследования).
  • Методы по умолчанию неявно public abstract.
  • default метод — метод с реализацией внутри интерфейса.
  • static метод — статический метод, вызывается через ИмяИнтерфейса.метод().
  • private метод (с Java 9) — для переиспользования общего кода между default методами.

Множественная реализация и Конфликт default методов:

Если два интерфейса содержат одинаковый default метод, компилятор выдает ошибку: "inherits unrelated defaults for move() from types...". Класс обязан переопределить данный метод у себя вручную (и при желании вызвать Интерфейс.super.метод()).

❓ Препод в .txt: «Скомпилируется ли код реализации интерфейса?» 
interface Clickable {
    void click();
}

class Button implements Clickable {
    @Override
    void click() {
        System.out.println("Clicked");
    }
}
Ошибка компиляции: attempting to assign weaker access privileges

В интерфейсе все методы без явного модификатора неявно public abstract! В классе Button метод void click() не имеет модификатора, то есть является package-private. Происходит сужение доступа с public до package-private, что запрещено. Необходимо строго написать public void click().

❓ Препод в .txt: «Что будет при реализации двух интерфейсов с конфликтом default методов?» 
interface FastRun {
    default void run() { System.out.println("Fast"); }
}
interface SlowRun {
    default void run() { System.out.println("Slow"); }
}

class Athlete implements FastRun, SlowRun {
    @Override
    public void run() {
        FastRun.super.run();
    }
}
// В main:
new Athlete().run();
Скомпилируется и выведет: Fast

Конфликт успешно разрешен, потому что класс Athlete явно переопределил метод run() и с помощью синтаксиса FastRun.super.run() указал, реализацию какого именно интерфейса вызывать.

7. Класс java.lang.Object (Слайд 40)

Определение из лекции: java.lang.Object

java.lang.Object — родитель всех классов в Java. Любой класс, даже если вы не пишете extends, автоматически наследуется от Object.

Содержит базовые методы, которые есть у каждого объекта:

  • toString() — строковое представление.
  • equals(Object obj) — сравнение на равенство (по умолчанию через ==).
  • hashCode() — хеш-код.
  • getClass() — получение класса объекта в runtime.
  • clone() — создание копии (требует реализации маркерного интерфейса Cloneable).
  • wait(), notify(), notifyAll() — методы для многопоточной синхронизации.
❓ Препод в .txt: «Что выведет main при сравнении двух одинаковых по содержимому объектов?» 
class Box {
    int weight;
    Box(int w) { this.weight = w; }
}

public class Main {
    public static void main(String[] args) {
        Box b1 = new Box(50);
        Box b2 = new Box(50);
        System.out.println(b1.equals(b2));
        System.out.println(b1 == b2);
    }
}
Вывод: false, false

В классе Box не переопределен метод equals() из java.lang.Object. По умолчанию метод equals() в классе Object выполняет сравнение ссылок оператором == (проверяет, указывают ли ссылки на одну и ту же область памяти в Heap). Так как это два разных объекта new Box(), оба сравнения вернут false.
